# ADR-004: Qdrant и векторный поиск вместо передачи всего корпуса модели или только поиска по словам

**Статус:** Принято
**Дата фиксации:** 22.09.2026  
**Область:** корпус правил, поиск, векторное хранилище и оценка RAG 

---

## 1. Контекст

Корпус правил MVP невелик и теоретически может целиком помещаться в контекстный запрос к модели. Тем не менее в рамках требований к учебному проекту рекомендовано использовать полноценный RAG, чтобы освоить этот подход, отдельно оценивать поиск, отслеживать происхождение сведений и предусмотреть рост корпуса.
Корпус представлен файлами в формате Markdown.

---

## 2. Основания для принятия решения

- требование курса использовать/обосновать RAG;
- практический опыт загрузки документов, векторизации, работы с векторной базой данных и повторного ранжирования;
- метаданные об источнике и разделе, ссылки на источники;
- фильтрация по версии, категории и типу правила;
- отдельные показатели поиска на эталонном наборе;
- возможность роста корпуса;
- отделение обновления базы знаний от формирования запроса к модели;
- возможность локального запуска через Docker Compose.

---

## 3. Рассмотренные варианты

### Вариант A — весь корпус в запросе к модели

Все документы передаются модели без предварительного поиска.

### Вариант B — поиск по словам с BM25 без векторизации

Поиск опирается на слова и индекс без внешнего сервиса векторизации и векторного хранилища.

### Вариант C — PostgreSQL/pgvector

Векторы хранятся вместе с реляционными данными с помощью расширения PostgreSQL.

### Вариант D — векторный поиск в Qdrant с фильтрами и повторным ранжированием

Отдельное специализированное векторное хранилище и управляемая загрузка с индексацией.

---

## 4. Сравнение

| Критерий | A. Весь корпус | B. Поиск по словам | C. pgvector | D. Qdrant |
|---|---|---|---|---|
| Простота при малом корпусе | Очень высокая | Высокая | Средняя | Ниже |
| Поиск по смыслу | Нет | Ограничен | Полноценный | Полноценный |
| Фильтры по метаданным | В запросе или приложении | Возможны | Поддерживаются | Поддерживаются |
| Отдельный сервис | Нет | Необязателен | Новая БД не требуется | Да |
| Возможности изучения и оценки RAG | Ограничены | Средние | Широкие | Широкие |
| Возможность роста корпуса | Ограничена контекстом модели | Средняя | Средняя/высокая | Высокая |
| Затраты на эксплуатацию | Низкие | Низкие | Усложняется общая БД | Дополнительный сервис |
| Ясность первичного источника | Корпус | Корпус и индекс | Риск смешения данных приложения и векторов | Корпус отдельно, Qdrant производен |

---

## 5. Решение

Использовать Qdrant как отдельный производный векторный индекс и реализовать поиск по смыслу с фильтрами по метаданным и повторным ранжированием.

Корпус документов Markdown остаётся первичным источником данных. Индекс Qdrant можно перестроить; он не хранит подлинники нормативных документов, профили сотрудников, решения по правилам или историю заявок.

Для нынешнего малого корпуса передача всех документов модели тоже может оказаться удачным решением. Qdrant выбран осознанно ради полноценного RAG, отдельной оценки поиска и возможности роста корпуса.

---

## 6. Положительные последствия

- исходный корпус отделён от производного индекса;
- поиск по смыслу помогает находить правила при различии формулировок;
- метаданные позволяют учитывать версию, категорию и происхождение сведений;
- поиск оценивается на эталонных примерах;
- структурированные данные превращаются в ссылки на источники;
- корпус может расти без включения всего текста в запрос к модели;
- векторный поиск не нагружает Application PostgreSQL.

---

## 7. Отрицательные последствия и долг

- дополнительный контейнер, том данных, проверки работоспособности, восстановление и клиентская библиотека;
- внешний сервис векторизации добавляет затраты, задержку и точку отказа;
- малый корпус может не оправдать сложность.

## 8. Риски и контроль

| Риск                                 | Контроль для MVP                                            | Необходимое изменение для Pilot                                       |
| ------------------------------------ | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| Расхождение индекса и источника      | Версии и метаданные                                         | Описание состава выпуска, контрольная сумма и связь с выпуском        |
| Ошибка загрузки                      | Сбой при начальной загрузке останавливает запуск            | Смена коллекций и возврат к прежнему псевдониму                       |
| Устаревшие правила                   | Жёстко заданная точная версия                               | Период действия и утверждение владельцем                              |
| Низкая релевантность                 | Векторный поиск, ранжирование по словам и эталонные примеры | Порог, устранение повторов, настройка и отдельные контрольные примеры |
| Вредоносные инструкции во фрагментах | Фильтры и очистка                                           | Реестр доверенных источников и правила проверки содержимого           |
| Утрата индекса                       | Возможность перестроить его из корпуса                      | Снимок данных, время восстановления и проверка эталонным набором      |

## 9. Условия пересмотра

- корпус остаётся малым, а передача его целиком модели обеспечивает сопоставимое или лучшее качество при меньших затратах;
- задержка и затраты на эксплуатацию Qdrant несоразмерны пользе;
- корпоративная платформа устанавливает стандарт для другого векторного хранилища;
- PostgreSQL/pgvector снижает совокупную стоимость владения без смешения ответственности за данные;
- требования к месту хранения данных исключают внешний сервис векторизации;
- проверка на эталонном наборе показывает недостаточность векторного поиска;
- появляется структурированный источник знаний и правил, уменьшающий потребность в поиске по смыслу.

При пересмотре варианты следует сравнивать на одном наборе примеров по качеству, задержке, стоимости, безопасности и сложности эксплуатации.
